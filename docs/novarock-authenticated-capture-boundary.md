# Nova Rock 2027 authenticated raw-card capture: boundary decision

Scope: isolated branch at 5270a6f5 (draft PR #288). This is a design/blocker, **not** a capture, attestation, approval or deployed-parser claim. No route, migration, persisted record, source mutation, candidate transition, provider call or network request is added here.

## Inspected boundary

- Passkey login verifies a credential and calls `createSession`. `currentUser` re-reads the cookie token hash, unexpired Session and current User; `currentAdmin(["ADMIN"])` additionally enforces the `ADMIN_EMAILS` allowlist. The generic `requireAdminActor` does **not** enforce that allowlist. Existing password login can also create a Session: an ADMIN session is authenticated, but the session schema does not attest which login method created it. A new record must not claim a passkey ceremony if it only has a session.
- `rejectUntrustedOrigin` rejects missing Origin, but falls back to the incoming request URL when `APP_URL` is unset. A sensitive capture route should require configured `APP_URL` as well as exact Origin. Request bodies must contain only an exact seal key; reviewer ID/email/session token, bytes, URL, headers, HTTP status and timestamp must never be accepted from the body.
- `fetchSource` is not an independent strict observer: it accepts configured headers/alternate fetch URL and follow-link pattern, follows redirects and retries. Its attempt provenance does not bind original complete response bytes. `verifyNovaRockCardDocument` independently validates supplied complete bytes and all 44 ordered tuples, but explicitly grants authority NONE and does not establish acquisition. `verifyNovaRockCardObservation` does fresh Serializable source/seal/candidate checks, but receives caller bytes and writes nothing.
- The content seal and draft validator fence historical/tied attempts, source generation/lease drift and catalogue changes, respectively. Neither authenticates a separate capture nor a deployed parser revision. The reviewed markup fixture is a transcription, not the original document. The controller's read-only recapture (216,722 bytes, SHA-256 cd0ffee8e50b30c67a5f755d0d0bf49930b83f1766adb667b781b5f404af214e) is useful correlation, **not** authenticated in-process provenance or permission to create a record.

## Narrow implementation contract for a later reviewed change

1. A private POST under the admin route must reject absent/untrusted Origin, require configured APP_URL and freshly resolve `currentAdmin(["ADMIN"])`. Obtain the session token hash **inside the server process** from the cookie; never accept actor/session fields from JSON. Only an exact seal ID may be input. Prefer a refactor that exposes a safe internal session identity primitive rather than re-implementing authentication from a body or trusting the pre-fetch User object.
2. A new dedicated transport, independent of `fetchSource`, must issue one direct HTTPS GET to the literal `https://www.novarock.at/lineup/`: verified TLS host/certificate, no proxy/provider imports, auth/cookies, caller headers, redirected URL (even same host), alternate URL, fallback or retry. Enforce one total deadline across DNS/connect/headers/body, header bound, identity encoding, HTTP 200, HTML UTF-8, exact final target, complete stream and <=512 KiB original bytes. Cancel and discard partial/oversized/late responses. The transport API must not take a URL, response object, bytes or fetch implementation from its caller. Test seams must not exist in the production entry point.
3. Preserve the complete original byte sequence, SHA-256 and capture-completion time in a new append-only record together with the 44 ordered independently parsed `{caption, officialUrl, day, billing, position}` tuples. Include exact content seal, candidate, source, attempt, source configuration generation/lease revision, authenticated reviewer and session reference. Keep raw bytes in restricted storage/DB, not Git or public response. A hash alone is not an immutable document reference.
4. After network completion, a single bounded Serializable transaction must lock source, run/attempt/candidate, festival/edition, session and User in a documented consistent order. Compose `verifyNovaRockContentSealInTransaction` and the full observation checks in that same transaction; do not call a separate completed verification transaction and then INSERT. Require exact source ID `cmuaee22i00xy6ncnc5uf6xxk` and edition ID `cmuaee1xc00tf6ncn76ea3pu2`, enabled direct official_markup config and matching sealed provenance/generation/lease, quiescent lease, original PENDING/REVIEW lineage, no competing source, newest untied attempt, same seal/content digest, live unexpired Session for the same User, current ADMIN role and allowlisted email immediately before INSERT. Serialize concurrent source/attempt/edition/session changes; propagate 40001/P2034 for a fresh attempt, never silently retry a stale capture.
5. Use restrictive FKs, uniqueness for seal/candidate/attempt, database raw-byte hash and size checks, UPDATE/DELETE/TRUNCATE prevention, and insert lineage checks. An INSERT does not change candidate reviewState, source, catalogue, refresh queue or playlist. Every returned/read result must say authority NONE and explicitly retain independent deployed-parser and artist-ID/review-decision blockers. No publisher may consume this record as approval by itself.

## Required proof before committing a capture implementation

Offline tests must prove redirect refusal, missing/duplicate status and content headers, bad type/encoding, partial stream, TLS/timeout/cancellation, oversized body, no retry and no injected headers/URL/credentials; verify byte-for-byte digest and 44 ordered cards. A fresh isolated localhost disposable PostgreSQL database must run migrations and exercise authenticated success plus revoked/expired session, demoted/unallowlisted reviewer, competing same-seal inserts, append-only triggers, exact source/edition drift and deterministic Serializable writer-first races. Compare entire original candidate lifecycle, source config, catalogue, publications and provider queue before/after. No tests may contact the official host or production. A test-double returning fixture bytes does not prove network provenance; the production transport must be separately reviewed against its fixed-target construction.

**Blocker at the design snapshot:** the codebase had a usable in-process ADMIN session boundary, but no transaction-bound session identity primitive, strict independent transport, or immutable authenticated raw-document store. Creating an apparently authoritative row from the existing caller-byte verifier, controller recapture or fixture would be false provenance. No such row is introduced until the complete transport, schema and PostgreSQL concurrency evidence above are implemented and independently reviewed. This blocker does not assert that authenticated capture is impossible; it prevents a partial implementation from being mistaken for proof.

**Subsequent isolated prerequisite (this branch):** `lib/ingestion/novarock-https-transport.ts` now implements only the fixed-target, single-request HTTPS transport. Its result retains original bytes, SHA-256 and completion time but grants authority `NONE`. Mocked offline transport tests do not establish a real official-host capture or network provenance. It is not imported by an admin route, verifier, database writer or publisher. Transaction-bound reviewer/session authentication, append-only raw-document storage, the in-transaction verification and concurrency proof, deployed-parser attestation and artist-ID/review decision remain separate blockers.
